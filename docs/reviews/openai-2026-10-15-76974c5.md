Major, lib/redmine_editauthor/hook.rb:71-86
Problem: Default scope 'project_add_issues' excludes users who are project members via groups, even if their group’s role allows :add_issues. The query limits to Member.user_id (direct user memberships) and never includes users whose membership is solely through a group.
Failure scenario: Create Group G, add it to Project P with a role that has :add_issues. Add User U only to G (no direct membership). With the default setting (authors_scope=project_add_issues), open New Issue or Edit Issue in P. U is allowed to add issues via the group but is missing from the author select, so U cannot be chosen as author.
Fix: Build the list from project.users (which includes group members) and filter by permission, or join through groups. Example (keeps admin project-members as specified):
  def possible_authors(project)
    case authors_scope
    when 'project_members'
      project.users.sorted
    when 'any_role'
      # keep existing behavior (or also include group-based memberships if desired)
      ...
    else # project_add_issues
      users = project.users.active.sorted
      # include project-member admins; allowed_to? covers add_issues via user or group membership
      users.select { |u| u.admin? || u.allowed_to?(:add_issues, project) }
    end
  end
If you prefer SQL: include users joined via groups_users when Member.principal is a Group, but that is more complex; the allowed_to? approach is correct and includes group-based permissions.
Resolution: not a defect. Redmine stores a member row per group user (inherited from the group), so `Member.user_id` includes group members. Shown by the new test "default scope includes users who are members through a group", which passes.
